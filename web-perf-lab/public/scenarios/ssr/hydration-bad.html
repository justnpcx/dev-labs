这才是 SSR 真正的坑
所有人都盯着 FCP/LCP 优化，做完 SSR 指标很漂亮 —— 但用户点按钮没反应，体感是"这网站好卡"。

衡量这件事的指标叫 INP（Interaction to Next Paint）， 而 SSR 页面最常见的 INP 问题就是 hydration 太长。
为什么必须"重跑一遍"
服务端渲染出来的只是一堆 HTML —— 没有任何事件监听。 客户端必须重新执行一遍组件、和现有 DOM 比对、再把事件挂上。
这一步省不掉，只能想办法别一口气做完。

// 一口气把 1500 个节点全部 hydration 完 —— 主线程被独占
function hydrateAll(root, props) {
  for (let i = 0; i < root.children.length; i++) {
    hydrateNode(root.children[i], props.items[i]);   // ★ 同步循环
  }
}

// hydrateNode 里做的事（框架也一样）：
//   ① 重新执行组件，算出"应该长什么样"
//   ② 和现有 DOM 比对（reconciliation）
//   ③ 挂事件监听
