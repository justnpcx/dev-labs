预期：内容在 约 0.7 秒后才出现
HTML 里 #app 是空的 —— 内容全靠 JS 后来填。
为什么这叫"问题版"
浏览器拿到 HTML 时**里面什么都没有**，必须： 下载 JS → 执行 → 发请求拿数据 → 再渲染。
这一串是串行的，用户全程看着白屏。

更糟的是：搜索引擎爬虫、社交平台的链接预览、 禁用 JS 的用户 —— 看到的都是这个空壳。
一个常见反驳
"我们有骨架屏啊。" —— 骨架屏只是把白屏换成了灰色方块， 首屏可见时间一点没提前。真正的解法是让 HTML 本身就带内容。

页面的 HTML 长这样

<body>
  <div id="app"></div>      <!-- ★ 空的 -->
  <script src="/bundle.js"></script>
</body>

// bundle.js 里：
fetch('/api/products')          // ① 先等网络
  .then(r => r.json())
  .then(({ items }) => {
    app.innerHTML = renderList(items);   // ② 再建 DOM
    attachHandlers();                    // ③ 再挂事件
  });

白屏期到底有多长

阶段耗时
HTML 到达很快（因为是个空壳，文件很小）
下载 + 解析 JS取决于 bundle 大小
请求数据600ms（本场景）
构建 DOM + 挂事件取决于条目数

四段加起来才是用户看到内容的时刻。SSR 把第 3、4 段挪到了服务端 —— HTML 到达时内容就已经在里面了。
