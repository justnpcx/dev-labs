六种断点，逐个练

  1. 普通断点 — 最基础
  2. 条件断点 — 只在满足条件时停
  3. 日志点 — 不停，只打日志
  4. DOM 断点 — 节点被改时停
  5. Fetch/XHR 断点 — 请求发出时停
  6. 事件监听断点 — 事件触发时停
每个练习的详细步骤写在右边对应的区块里。

演示区

① 普通断点 / ② 条件断点 / ③ 日志点

点下面的按钮会跑一个 1~20 的循环。
这个循环在 breakpoint-demo.js 的 loopSum() 里。

练习操作
普通断点 Sources → breakpoint-demo.js → 点 sum += i * i 那行的行号 → 出现蓝色标记 → 点按钮， 然后一直点「继续执行」，看 i 从 1 涨到 20
条件断点 右键那个行号 → Add conditional breakpoint → 输入 i === 7 → 点按钮。
这次只停一次，直接停在 i === 7
日志点 右键行号 → Add logpoint → 输入 i = {i}, sum = {sum} → 点按钮。
代码不会停，但 Console 里会打出 20 行记录
日志点为什么比 console.log 好
· 不用改代码，不用重新部署
· 能访问当前作用域的所有变量，包括你事先不知道要看的那些
· 用 {变量名} 插值，比字符串拼接清楚
· 断点太多会打断执行流，日志点不会 —— 排查循环/高频函数时特别有用

④ DOM 断点

下面这个方块会被改属性、改样式、改文本。 你想知道是哪一行代码改的。

目标
练习操作
属性修改断点 切到 Elements 面板 → 找到 #domTarget → 右键 → Break on → attribute modifications → 回来点按钮 → 会停在改属性的那一行
子树修改断点 同上，但选 subtree modifications —— 子节点被增删改时停
节点移除断点 选 node removal —— 这个节点被从 DOM 里删掉时停

典型用途：页面上某块内容莫名其妙变了，但你在代码里搜不到谁改的 （可能是第三方库、可能是某个定时器）。DOM 断点能直接抓到凶手。

⑤ Fetch / XHR 断点

点下面的按钮会请求 /api/item/42（服务端会延迟 300ms）。

练习操作
按 URL 断点 Sources 面板右侧 → XHR/fetch Breakpoints → 点 + → 输入 item/42 → 点按钮。
会在 fetch() 调用处停下来
看调用栈 停下来后看右侧 Call Stack —— 能看到是谁发起了这个请求， 一层层往上翻就知道触发链路

典型用途：接口返回不对，但不知道是哪个页面、哪个组件发的请求。 按 URL 断点 + Call Stack 能直接定位。

⑥ 事件监听断点

练习操作
在元素上打断点 Elements 面板选中这个按钮 → Event Listeners 标签（在 Styles 旁边）→ 展开 click → 点右边那个链接 → 跳到处理函数
用 Sources 面板 Sources 右侧 → Event Listener Breakpoints → 展开 Mouse → 勾 click → 点按钮，会停在所有 click 处理函数里

典型用途：不知道某个点击效果是哪段代码做的。 全局事件断点会停在所有 click 处理函数上，挨个看调用栈就能找到。

⑦ 加分项：Blackboxing（屏蔽第三方库）

调试时最烦的是一步步跳进 jQuery / React 内部。 Blackbox 能让调试器跳过指定脚本。

做法步骤
方式一 在 Sources 里右键某个文件 → Blackbox script
方式二 Settings（F12 → 右上齿轮）→ Ignore List → 加入匹配规则，如 /node_modules/

黑盒之后，单步调试（F11）会自动跳过这些文件，直接停在你自己的代码里。 排查问题时能省下大量"跳进跳不出"的时间。

⑧ 加分项：Live Expressions

在 Sources 面板右侧找 Watch 旁边的 Live Expressions（有个眼睛图标）。
添加一个表达式（比如 document.querySelectorAll('*').length）， 它会实时刷新，不用打断点也不用写 console.log。

调样式、看状态变化时非常方便。
