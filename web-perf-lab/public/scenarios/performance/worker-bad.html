重活跑在主线程上

看优化版 →

DevTools 观察清单

  1. 先点「开始计数」—— 上面那个数字每秒涨 60 左右
  2. 再点「算 40 次斐波那契(38)」
  3. 看数字：直接冻住，一下都不涨
  4. 试着点「开始计数」按钮 —— 点不动，事件在排队
  5. Performance 面板录一次，看 Main 轨道那一整块红色长任务
  6. 看 Tasks 列表里的耗时，这就是主线程被独占的时长
预期：计数完全停止，按钮无响应
整个过程大概 1.5~3 秒（取决于机器）。
为什么"计数器停了"是最直观的证据
requestAnimationFrame 回调必须等主线程空闲才能跑。 主线程被同步循环占住，rAF 就排不上队 —— 计数自然停。

这也是用户感受到的"页面卡死"：不是渲染慢，是根本没机会渲染。

问题出在这一行

// 点击处理里直接跑重活 —— 主线程被独占，谁都别想跑
button.onclick = () => {
  const r = fib(38);          // ← 同步递归，纯 CPU
  render(r);
};

// 这期间：
//   requestAnimationFrame  → 排不上队，动画停
//   下一次点击            → 排在队列里，按钮"点不动"
//   渲染                  → 没机会发生

哪些活该搬走

该搬去 Worker只能留主线程
大数组排序 / 过滤 / 聚合任何碰 DOM 的操作
JSON 解析大报文window / document 相关
加解密、压缩、图片处理布局、绘制、合成
语法高亮、Markdown 渲染事件监听、路由

判断标准很简单：这段代码碰不碰 DOM？不碰，就能搬。
