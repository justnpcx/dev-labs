一万条全部塞进 DOM

看优化版 →

DevTools 观察清单

  1. 点「加载 10000 条」—— 注意它卡了多久
  2. 看页面下方报出的渲染耗时和DOM 节点数
  3. 在列表里快速滚动 —— 明显掉帧、发涩
  4. Performance 面板录一次滚动，看 Main 轨道密集的红块
  5. 切到 Memory 面板 → 点垃圾桶图标做一次堆快照
  6. 看 Elements 面板，数一数 .vrow 有多少个
预期：渲染耗时 几百毫秒，DOM 节点数 3 万以上
滚动时帧率掉到 20~30fps。
为什么节点数比"条数"多这么多
每条记录渲染成 div > b + span 三个节点，一万条就是三万个。 再加上样式计算、布局、绘制 —— 浏览器每次滚动都要在这棵大树上干活。

内存上更明显：每个 DOM 节点在 Chrome 里大约占 1KB 左右（含样式和布局对象）， 三万节点就是几十 MB。

问题出在这一行

const { items } = await (await fetch('/api/items?n=10000')).json();

// 一万条，一条不落地塞进 DOM
list.innerHTML = items.map((it) =>
  `<div class="vrow"><b>#${it.id}</b> ${it.name}</div>`
).join('');

// 用户只能看到 7~8 条，剩下 9992 条在白白占内存、拖慢布局。

长列表的三种做法

做法DOM 节点数代价
全量渲染O(n)一万条就卡死
虚拟滚动O(可视区)要自己管滚动位置、行高
分页 / 无限滚动O(已加载)滚久了还是会积累

注意分页并没有解决问题，只是把它推迟了 —— 用户一直往下滚，节点还是越积越多。真正的解法是虚拟滚动。

别急着上库
虚拟滚动的核心逻辑其实只有二十来行（见优化版）。 只有在需要动态行高、横向虚拟、粘性分组这些复杂需求时， 才值得引入 react-window / vue-virtual-scroller 这类库。
