用 transform 做动画

← 回问题版

DevTools 观察清单

  1. Rendering 面板：勾上 Paint flashing 和 Layer borders
  2. 点「开始动画」
  3. 这次方块不闪绿框（没有重绘），而且有橙色边框（独立合成层）
  4. Performance 面板录制，看 Main 轨道 —— 应该几乎是空的
  5. 切到 Layers 面板（可能要在 More tools 里找），能看到这个元素被提升成了独立层
  6. 对比问题版：那边 Main 轨道被 Layout/Paint 填满
预期：Main 轨道上没有 Layout，动画跑在合成线程上
即使主线程被 JS 占住，这个动画照样流畅。
为什么 transform 能跑在合成线程
元素被提升为独立合成层后，浏览器会把它预先绘制成一张纹理。 移动它只需要 GPU 把这张纹理挪个位置 —— 不需要重新计算布局， 也不需要重新绘制。所以主线程忙的时候动画也不卡。

演示

点一下开始，注意绿框和橙框 
等待开始…

改动就一行

// ❌ 问题版
mover.style.left = x + 'px';       // 触发布局

// ✅ 优化版
mover.style.transform = `translateX(${x}px) translateY(${y}px)`;
// 只影响合成，不碰布局

三个层次的做法

做法主线程参与适用
JS 每帧改 transform 要（rAF 回调） 需要根据逻辑动态计算位置
CSS transition / animation 不要 固定的过渡和循环动画
Web Animations API 只在开始时 需要 JS 控制播放，但要流畅

最彻底：交给 CSS

@keyframes slide {
  from { transform: translateX(0); }
  to   { transform: translateX(400px); }
}
#mover {
  animation: slide 2s ease-in-out infinite alternate;
  will-change: transform;
}
/* 浏览器会在合成线程上跑这个动画，主线程完全不参与 */

Web Animations API（需要 JS 控制时用）

mover.animate(
  [{ transform: 'translateX(0)' },
   { transform: 'translateX(400px)' }],
  { duration: 2000, iterations: Infinity, direction: 'alternate' }
);
// 声明式，由浏览器调度 —— 比手写 rAF 循环更省
will-change 别滥用
每个合成层都要占显存。
给几十个元素加 will-change: transform， 会创建几十个层，显存暴涨，低端设备直接崩。
正确做法：动画开始前加，结束后移除；或者只给确实会动的少数元素加。
