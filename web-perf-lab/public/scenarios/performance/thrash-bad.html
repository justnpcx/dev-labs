  1. 打开 Performance 面板，点录制
  2. 点「布局抖动版」按钮，等它跑完（约 1 秒）
  3. 停止录制，放大 Main 轨道
  4. 你会看到紫色的小块（Layout）反复出现，几百次
  5. 看底部 Summary：Rendering + Painting 占了绝大部分时间
  6. 对比优化版：Layout 只出现一两次
预期：Layout 触发 数百次，总耗时 500ms+
优化版：Layout 只触发 1 次，总耗时降到几十 ms
什么叫「强制同步布局」
浏览器为了性能，会把布局计算攒起来批量做。 但如果你在改完样式之后立刻去读布局属性 （offsetHeight、offsetTop、 getBoundingClientRect()、getComputedStyle()…）， 浏览器就必须立刻停下攒批，同步算一次布局才能给你准确答案。

在循环里读→写→读→写，就变成了每轮都强制算一次布局， 这就是"布局抖动"（layout thrashing）。

罪魁祸首：读写交替

for (let i = 0; i < boxes.length; i++) {
  const h = boxes[i].offsetHeight;    // ← 读：强制同步布局
  boxes[i].style.width = (h * 2) + 'px';  // ← 写：让布局失效
}
// 下一轮又读 → 又要重新算布局 → 每一轮都算一次

哪些属性会触发布局

类别属性
几何属性 offsetTop/Left/Width/Height
clientTop/Left/Width/Height
scrollTop/Left/Width/Height
方法getBoundingClientRect()
getClientRects()
计算样式getComputedStyle()
窗口window.innerWidth / innerHeight
滚动element.scrollIntoView()

记忆口诀：凡是需要"真实像素尺寸/位置"的读取，都可能触发布局。
