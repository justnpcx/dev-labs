DevTools 观察清单

  1. 点「加载 10000 条」—— 这次几乎是瞬间完成
  2. 看报出的 DOM 节点数：几十个，不是三万多
  3. 快速滚动列表 —— 顺滑，不掉帧
  4. 滚动时看 Elements 面板：.vrow 的数量始终不变
  5. 注意行号在变 —— DOM 节点被复用了，不是每次新建
  6. Memory 面板做一次堆快照，对比问题版的内存占用
预期：渲染耗时 个位数毫秒，DOM 节点数 约 30 个
一万条和一百万条，DOM 开销完全一样。
核心思路只有一句话
DOM 里永远只放"当前看得见的那些行"， 用一个撑高的占位元素骗过滚动条，滚动时换内容。

复杂度从 O(总条数) 降到 O(可视区高度 / 行高)。

核心逻辑就这些

const ITEM_H = 56;                     // 固定行高，是虚拟滚动的前提
const VIEW_H = vp.clientHeight;

function render() {
  const start = Math.floor(vp.scrollTop / ITEM_H);
  const end   = start + Math.ceil(VIEW_H / ITEM_H);

  // 撑高占位元素，让滚动条长度是对的
  spacer.style.height = (items.length * ITEM_H) + 'px';

  // 只把可视区那几行放进 DOM，并用 translateY 摆到正确位置
  pool.style.transform = `translateY(${start * ITEM_H}px)`;
  pool.innerHTML = items.slice(start, end + 1).map(rowHtml).join('');
}

vp.addEventListener('scroll', render, { passive: true });

为什么用 translateY 而不是 top

translateY 只触发合成，不触发布局和重绘； top 会。滚动是每秒 60 次的高频操作， 这个差别在低端机上很致命（同 动画属性 那个场景）。

虚拟滚动的三个难点

难点怎么办
行高不固定预估 + 实测回填，或干脆要求固定行高
滚动太快出现白屏上下多渲染几行做缓冲区（本页多渲染 1 屏）
行内有图片/异步内容先占位再回填，避免加载完成时行高跳动

固定行高是最省事的做法。如果设计上必须动态行高， 复杂度会上升一个量级 —— 这时候才值得考虑用现成的库。
