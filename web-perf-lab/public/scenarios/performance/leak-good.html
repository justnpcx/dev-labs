改法一：用完就不留引用

function createAndRemove() {
  const container = document.getElementById('stage');

  for (let i = 0; i < 100; i++) {
    const node = document.createElement('div');
    node.textContent = '...';

    // ✅ 用 AbortController 管理监听器，随时能一次性全部解绑
    node.addEventListener('click', handler, { signal: controller.signal });

    container.appendChild(node);
    container.removeChild(node);
    // ✅ 不往任何长期存活的地方存引用 —— 出了这个作用域就能被回收
  }
}

改法二：AbortController（现代解绑方式）

const controller = new AbortController();

// 一次性挂多个监听
window.addEventListener('scroll', onScroll, { signal: controller.signal });
window.addEventListener('resize', onResize, { signal: controller.signal });
document.addEventListener('click', onClick, { signal: controller.signal });

// 组件卸载时，一行全部解绑
controller.abort();

以前要一个个 removeEventListener，还得保证函数引用一致， 很容易漏。AbortController 是一把全解， 漏不掉 —— 尤其适合一个组件挂了十几个监听的场景。

改法三：WeakMap 做缓存

// ❌ Map：key 被强引用，对象永远不释放
const cache = new Map();
cache.set(domNode, computedValue);

// ✅ WeakMap：key 是弱引用，domNode 被回收时条目自动消失
const cache = new WeakMap();
cache.set(domNode, computedValue);

改法四：定时器要清

// ❌ 组件卸载了，interval 还在跑，闭包里的 DOM 一直被引用
setInterval(() => update(el), 1000);

// ✅ 存下 id，卸载时清掉
const timer = setInterval(() => update(el), 1000);
// 卸载时：
clearInterval(timer);
怎么定位"是谁在引用"
堆快照里选中一个 Detached 节点 → 底部 Retainers 面板 → 展开引用链，一直往上找。
最后那条链的顶端通常就是罪魁祸首：某个全局数组、某个没解绑的监听器、 或者某个还在跑的定时器。
Retainers 面板是定位内存泄漏的核心工具，比看堆大小有用得多。
