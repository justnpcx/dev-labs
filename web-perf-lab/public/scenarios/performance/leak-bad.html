Detached DOM 泄漏

看优化版 →

DevTools 观察清单

  1. 打开 Memory 面板（不是 Performance）
  2. 先点一次「拍堆快照」，作为基线
  3. 点 5 次「创建并移除 100 个节点」
  4. 再点一次「拍堆快照」
  5. 在第二个快照里筛选 Detached（顶部下拉选 "Detached"）
  6. 对比两个快照的 Retained Size，看涨了多少
  7. 点「手动 GC」后再拍一次 —— 涨的部分不会回落，这就是泄漏
预期：Detached 节点数持续增长，手动 GC 也降不下来
优化版：GC 后回落到基线
什么叫 Detached DOM
节点已经从页面上移除了（removeChild）， 但 JS 里还持有引用 —— 可能在一个数组里、一个闭包里、 或者被某个事件监听器捕获着。

对浏览器来说：你还有引用，我就不敢回收。 于是这些节点连同它们的子节点、样式、事件监听器， 一直占着内存，直到页面刷新。

问题代码

const detached = [];          // ← 模块级数组，一直活着

function createAndRemove() {
  const container = document.getElementById('stage');

  for (let i = 0; i < 100; i++) {
    const node = document.createElement('div');
    node.textContent = '占位内容'.repeat(50);
    node.addEventListener('click', () => {});   // 监听器也一起泄漏

    container.appendChild(node);
    container.removeChild(node);      // 从 DOM 移除了

    detached.push(node);              // ❌ 但引用还在数组里
  }
}

真实项目里最常见的四种泄漏

类型典型写法
未清理的事件监听 组件卸载了，window.addEventListener 还在
未清理的定时器 setInterval 持有闭包，闭包里持有 DOM
全局缓存只增不减 用 Map 当缓存，从不 delete
闭包意外捕获 回调里引用了整个大对象，其实只用到其中一个字段
堆快照的对比方法
1. 拍快照 A → 操作 → 拍快照 B → 再操作 → 拍快照 C
2. 在快照 C 的顶部下拉选 Comparison，基线选快照 B
3. 按 Delta 排序，找增长最多的类型
4. 展开看 Retained Size（不是 Shallow Size）
5. 选中对象 → 底部 Retainers 面板看谁在引用它
