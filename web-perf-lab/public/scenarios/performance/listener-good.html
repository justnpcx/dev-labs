方式特点适合

在这个区域滚动试试

优化后的代码

let ticking = false;

area.addEventListener('scroll', () => {
  fired++;                              // 事件照样触发很多次
  if (ticking) return;                  // 已经排好队了，直接跳过
  ticking = true;

  requestAnimationFrame(() => {
    const top = area.scrollTop;         // 只在帧开始时读一次

    for (let i = 0; i < items.length; i++) {
      items[i].style.transform = `translateY(${top * 0.1}px)`;
    }
    ran++;
    ticking = false;                    // 允许下一帧再排队
  });
});

为什么这样就够了

浏览器一帧最多渲染一次。你在两次渲染之间算 100 遍， 用户看到的还是最后一次的结果 —— 前 99 遍纯属浪费。

requestAnimationFrame 的回调会在下一次渲染前执行， 所以它天然就是"每帧一次"的节拍器。

再加一层：读写分离

// 读和写分别放到不同阶段，避免强制同步布局
requestAnimationFrame(() => {
  const top = area.scrollTop;              // 帧内只读一次
  requestAnimationFrame(() => {
    items.forEach(el => el.style.transform = `...`);  // 再统一写
  });
});
还有一个更彻底的方案
如果只是做"跟随滚动"的视觉效果，根本不需要 JS： 用 CSS 的 position: sticky、 scroll-driven animations（animation-timeline: scroll()） 或者把元素提升到合成层（will-change: transform）， 浏览器会在合成线程上处理，主线程完全不参与。
