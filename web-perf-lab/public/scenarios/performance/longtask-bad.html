长任务阻塞主线程

看优化版 →

DevTools 观察清单

  1. 先看下面的心跳计数器 —— 它每 50ms 跳一次，说明页面是活的
  2. 打开 Performance 面板，点录制（●）
  3. 点「跑一个长任务」—— 注意计数器卡住不动了
  4. 等它跑完，停止录制
  5. 看 Main 轨道上那块又长又厚的黄色（Scripting）—— 上面会标红色三角，那就是 Long Task
  6. 看底部 Summary 里 Scripting 占了多少毫秒
预期：计数器冻结约 800ms
Main 轨道出现一个 >50ms 的长任务（红色三角标记）
为什么"卡"
浏览器主线程只有一个。JS 执行、样式计算、布局、绘制、 以及响应用户输入，全都排在这一条线程上。
一段同步 JS 跑 800ms，这 800ms 内：
  • 点击没反应
  • 输入框打不出字
  • 滚动不动
  • 连动画都掉帧（rAF 也排不上队）

罪魁祸首

function runLong(ms) {
  const deadline = Date.now() + ms;
  let x = 0;
  while (Date.now() < deadline) {     // ← 同步忙等，一口气占满主线程
    x += Math.sqrt(x + 1);
  }
  return x;
}

场景典型耗时
一次性渲染几千个 DOM 节点几百 ms ~ 数秒
大 JSON 的 JSON.parse几十 ~ 几百 ms
复杂计算没放 Worker不定
第三方脚本（埋点、A/B 测试）常见且难控
同步 XHR / 同步 localStorage取决于 IO
长任务的定义
Chrome 把超过 50ms 的任务算作 Long Task。 为什么是 50ms？因为这大致是人能感知到"卡"的阈值， 也是 60fps 下 3 帧的时间。
页面所有长任务的超时部分之和就是 TBT（Total Blocking Time）， 它是 Core Web Vitals 里 INP 的主要影响因子。
