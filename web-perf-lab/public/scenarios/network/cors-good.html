DevTools 观察清单

  1. 用 http://localhost:8082 打开本页（本场景必须本地访问，见问题版说明）
  2. Network 面板，勾 Disable cache
  3. 点「发 3 次请求」
  4. 数记录数 —— 这次应该只有 3 条，没有 OPTIONS
  5. 点开任意一条 → Headers → 看 Request Headers 里没有自定义头
  6. 对比问题版的 6 条，想想差的那 3 个 RTT 值多少毫秒
预期：3 次往返（省掉了一半）
在弱网下（每个 RTT 200ms），这就省了 600ms。

什么算「简单请求」

维度要求
MethodGET / HEAD / POST
请求头只能是「安全头」：
Accept, Accept-Language, Content-Language, Content-Type, Range 等
Content-Typetext/plain
multipart/form-data
application/x-www-form-urlencoded

三个条件全部满足才是简单请求，才跳过预检。

公网入口挂了 Cloudflare Access，而浏览器发预检时不带 Access 的 cookie， 请求会被 403 挡掉 —— 你在 Network 里看不到 OPTIONS。

但现实里经常躲不掉

这几种情况必须预检，优化方向不是"消掉预检"，而是"别重复预检"：

场景怎么办
要发 Authorization 头预检躲不掉，把 Max-Age 设大
要 PUT / DELETE同上
要发 JSON（application/json）同上，这是最常见的
同源请求根本不会有 CORS，用同源代理即可
最有效的优化：让它变成同源请求
用反向代理把 API 挂到同一个域名下（/api/* 转发到后端）， 浏览器就认为是同源 —— 没有 CORS，没有预检，连 Cookie 都省心。
这也是为什么很多前端项目在 nginx 里配 proxy_pass。

另一个坑：凭证请求不能用通配符

如果请求带了 Cookie（credentials: 'include'）， 服务端不能回 Access-Control-Allow-Origin: *， 必须回具体的源，并且加 Access-Control-Allow-Credentials: true。 这个报错信息很不直观，很多人卡在这里。
