DevTools 观察清单

  1. 打开 Network 面板，勾上 Disable cache
  2. 点下面的「开始加载」，观察 Waterfall 列
  3. 看这 7 个 /api/item/* 是不是排成一条阶梯（一个接一个）
  4. 看底部 Summary 的 Finish 时间
  5. 点任意一个请求 → Timing 标签，看 Stalled 那段有多长
预期：Finish ≈ 2.1 秒（7 × 300ms 相加）
每个请求的 Stalled 都很长 —— 它在等上一个请求结束，不是在等服务器。
这是最容易被误判的坑。
看到 Stalled 很长，很多人会以为"服务器慢"或"网络慢"， 其实服务器每个只花了 300ms —— 剩下 1.8 秒全是在排队等前一个。 这就是为什么必须看 Waterfall 而不是只看总时长。

为什么是串行

下面这段代码里，await 写在 for 循环内 —— 每次循环都必须等上一个请求完全结束才会发起下一个。 

for (let i = 1; i <= 7; i++) {
  const r = await fetch('/api/item/' + i);   // ← await 卡住了整个循环
  results.push(await r.json());
}
