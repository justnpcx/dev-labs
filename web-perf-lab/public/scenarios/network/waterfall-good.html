和问题版对比

写法总耗时
for + await~2100ms
Promise.all~300ms

快了 7 倍，而服务端一行代码都没改 —— 只是把「排队」改成了「同时发」。

注意别矫枉过正。
并行不是永远更好：
· 浏览器对同域名的并发连接数有限制（HTTP/1.1 通常 6 个）
· 几百个请求一起发会把连接池打满，反而更慢
· 有依赖关系的请求本来就必须串行

改了什么

把 await 从循环里挪出来 —— 先同时发起所有请求拿到 Promise， 再用 Promise.all 一起等结果。 

// 先把所有请求都发出去（不 await）
const promises = [];
for (let i = 1; i <= 7; i++) {
  promises.push(fetch('/api/item/' + i));
}
// 再一起等
const responses = await Promise.all(promises);

也可以用 await Promise.all([1,2,3,4,5,6,7].map(i => fetch('/api/item/' + i)))， 写法更短。
