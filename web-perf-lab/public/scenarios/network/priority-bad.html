LCP 图被降级到 Low

看优化版 →

DevTools 观察清单

  1. 打开 Network，务必勾上 Disable cache（否则图片命中缓存，什么都看不到）
  2. 右键表头 → 勾上 Priority 列
  3. 硬刷新 Ctrl+Shift+R
  4. 找到 /api/image 那条，看它的 Priority
  5. 看它的 Start time —— 是不是排在 CSS / JS 后面才出发
  6. 切到 Performance 面板录一次，看 LCP 标记落在哪个元素上、什么时候
预期：图片 Priority = Low，开始时间 ~0.8s —— 排在阻塞脚本后面
它是 LCP 元素，LCP 被拖到 1.0s 左右。
根因：loading="lazy" 用错了地方
懒加载是给首屏之外的图用的。加在首屏 LCP 图上， 浏览器会把它降到 Low 优先级、延后加载 —— 等于主动把自己的 LCP 推迟。

这是最常见的 LCP 事故，而且代码看起来"很优化"。

演示

下面这张图就是本页的 LCP 元素。它故意做成小文件（平滑渐变，几 KB）—— 这样"什么时候开始下载"这个差异才不会被下载耗时掩盖掉。 页面上方还有两个各 700ms 的阻塞脚本，把它的发现时间推后了 1.4 秒。

问题出在这一行

<!-- 首屏 LCP 图，却加了 loading="lazy" -->
<img src="/api/image?..." loading="lazy">

<!-- 没有 preload，没有 fetchpriority -->
<!-- 浏览器只能等 HTML 解析到这里，才"发现"这张图 -->

浏览器怎么给资源排优先级

资源默认优先级
阻塞渲染的 CSSHighest
head 里的同步 JSHigh
首屏普通 <img>High
loading="lazy" 的图Low
字体High（但发现得晚）

优先级决定了带宽怎么分。把 LCP 图降到 Low， 等于在一堆不重要的请求后面排队。
