gzip vs brotli

gzipbrotli
压缩率好更好（通常再小 15~20%）
浏览器支持全支持现代浏览器都支持
服务端到处都有需要较新版本

这个演练场的服务端会看 Accept-Encoding， 优先用 br，不支持才退回 gzip。

服务端怎么做的

const accept = req.headers['accept-encoding'] || '';

if (accept.includes('br')) {
  body = zlib.brotliCompressSync(body);
  headers['Content-Encoding'] = 'br';
} else if (accept.includes('gzip')) {
  body = zlib.gzipSync(body);
  headers['Content-Encoding'] = 'gzip';
}

// 重要：告诉缓存层"这个响应随 Accept-Encoding 变化"
headers['Vary'] = 'Accept-Encoding';
Vary: Accept-Encoding 很容易漏，漏了会出事故。
它告诉 CDN / 代理："同一个 URL，对不同 Accept-Encoding 的请求， 响应内容不一样，别混着缓存。"
不加的话，CDN 可能把 gzip 版本缓存下来，返回给一个不支持 gzip 的客户端， 对方拿到的就是乱码。

还有一个容易踩的坑

别对已经压缩过的格式再压缩。JPEG / PNG / WebP / MP4 / ZIP 内部已经没有冗余，gzip 一遍不仅省不了多少，还白白烧 CPU。
服务端一般按 Content-Type 白名单来开压缩： text/*、application/json、 application/javascript、image/svg+xml 开； 图片视频关。
